Introducing harness adapters: adapt your favorite model to your harness to improve performance and cost

推荐理由

团队的工具调用成本已经很高时，这篇文章能帮你估算，为固定编码框架训练适配器究竟值不值。

内容摘要

在 Pi 编码框架里训练适配器后，同一基础模型在 51 道高难题上的一次通过率从 39.2% 升至 64.7%。换到业务自动化任务，收益落入测量噪声。

让模型在实际使用的框架里训练

通用模型追求跨场景表现，却未必懂得怎样在你选的代理框架里高效使用工具。作者冻结 Qwen3.8-27B 的基础权重，为三个框架分别训练轻量适配器。训练不另写代理循环，而是让原版框架在沙箱里执行编码任务，由代理服务器记录模型实际生成的词元。奖励以测试判定的正确性为主，再给更高效的工具使用一点额外奖励。 原文章节

一次框架内训练的反馈路径

  1. 原版编码框架执行任务
  2. 记录模型输出与工具动作
  3. 测试用例判定完成情况
  4. 更新框架专用适配器

同一个 Pi，最难的题多做对了多少

作者关闭思考模式，让基础版和适配版各做一遍 SWE-bench Pro 最难的 51 题。在 Pi 中，专用适配器把一次通过率从 39.2% 提到 64.7%，新解出 15 题，也丢了原本能解的 2 题。在这套题上，三个框架分别只看两版都解出的题，专用版每题工具调用少 56%–72%；这不是全部任务的总成本降幅。 原文章节

延伸思考

换掉框架后，还值得为同一个适配器付训练成本吗？

作者改用 AutomationBench 自带的代理循环，测试了 300 道业务自动化任务。以全部断言通过为准，合并版的一次通过率为 23.7%，基础版为 23.0%，没有显示出明确的迁移收益。选型时，建议先用未参与训练的自家任务，在同一框架内比较通过率和每题开销；如果任务类型和代理循环都要换，就别把编码基准上的收益算进预算。 原文章节

首次入选　工具与执行　2026-11-18　OpenAI

Inside the Codex sandbox

推荐理由

如果你的代理能运行 shell、访问密钥或接入 MCP 服务，这篇文章能帮你判断，哪些权限需要分别配置。

内容摘要

Codex 默认允许修改工作区并阻止联网，却仍可能读到仓库外的敏感文件。接入外部工具时，还要确认它的启动命令是否也受沙箱约束。

工作区可写，不等于只能读工作区

Codex 在宿主系统上运行命令，子进程继承同样的限制。以 Git 仓库为工作区时，默认配置允许修改源码，但将 Git 元数据目录和 Codex 配置目录设为只读，并关闭网络。构建工具仍能在系统权限范围内读取仓库外的依赖，命令也因此可能读到敏感文件。若任务不该接触密钥，建议对存放密钥的路径明确设为拒绝访问。 原文章节

给 MCP 服务单独套一层沙箱

Codex 不会自动把通过标准输入输出通信的 MCP 服务放进沙箱，因为它无法可靠推断服务需要访问哪些文件和网络资源。文章以记忆服务为例：作者先建好数据目录并缓存固定版本的依赖，再用单独的权限配置离线启动，把写入范围限定在包缓存和服务数据目录。接入类似服务时，建议单独核对它的读写路径和联网需求。 定位原句

延伸思考

如何验证同一条权限规则在三种系统上都有效？

Codex 在三个平台上共用一套启动接口，但由各自的系统机制执行限制：macOS 用 Seatbelt，Linux 结合 bubblewrap 和系统调用过滤，Windows 正在兼容设备上转向 MXC。文章指出，Windows 在代理模式下会阻止直接连接外部主机，但宿主机的回环服务仍可访问。如果也要隔离本机开发服务，建议在目标系统上验证，别只检查外网是否被挡住。 原文章节

首次入选　身份与授权　2026-11-05　Cloudflare

Agents aren’t humans (but they kinda are)

推荐理由

适合正在做账号风控的工程师。按代理封禁可能影响它服务的所有人，原文拆开了账号归属、请求签名和用户授权。

内容摘要

云端代理替多人访问网站，认出代理不等于知道它代表谁。网站可以按操作风险索取必要信息，在能区分账号时只限制涉事账号，而不是封掉整个代理。

为什么封代理会误伤用户

文章用一名替四位客户跑腿的助理说明共享代理的难题：一位客户让她买手机，事后却否认授权。商家只见过助理，很难证明是谁下的单。银行也面临类似困境：当其中一人的行为触发风控，封掉助理会连带挡住另外三人。对网站来说，认出代理只是第一步；处理争议还得分清它这次代表谁，以及谁应为这次操作负责。 定位原句

代理签名能证明什么

Cloudflare 建议把代理身份和用户身份分开。Web Bot Auth 让代理签署请求，网站据此识别代理及其运营方，却不能只凭签名知道代理在替谁办事。用户侧只需按操作风险披露必要信息：有时网站只需要判断请求是否可信，不必知道用户是谁。如果一次访问经过多个代理或云浏览器，如何让网站识别整条中介链，仍有待定义。 定位原句

延伸思考

一个账号违规时，封禁应该落在哪一层？

据 Cloudflare 介绍，客户已能按代理查看流量并设置访问规则。开通账号滥用防护早期访问的站点，还能在登录和注册时识别代理；某个账号被滥用时，可以用防火墙规则按用户哈希标识处置，不必封掉整个代理。落地时可先用这些信号缩小封禁范围；如果用户对付款提出争议，仍需另行确认授权，不能把识别出账号当成授权凭证。 定位原句
